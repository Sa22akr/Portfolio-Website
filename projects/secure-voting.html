Django Secure Voting System

A structured voting platform designed to prevent duplicate votes, enforce fairness logic, and maintain relational data integrity.

Backend-Focused Django Relational Database Validation Logic Security Controls

Project Overview

This project was developed to simulate a secure digital voting environment where system integrity and fairness were prioritised. The objective was to eliminate common vulnerabilities such as duplicate voting, self-voting, and session manipulation.

The Problem

Many digital voting implementations rely heavily on frontend restrictions, making them vulnerable to manipulation. Without structured relational modelling and server-side validation, users can exploit logical loopholes.

The challenge was to enforce strict voting rules at the database and backend level.

Core Features

  • One-user-one-vote enforcement
  • Candidate self-vote prevention logic
  • Relational database modelling
  • Timestamp tracking for submissions
  • Admin-controlled candidate management
  • Session categorisation structure

My Role

Designed and implemented the backend architecture independently, focusing on relational modelling, validation logic enforcement, and system fairness.

Backend Engineering

  • Django ORM relational modelling
  • OneToOneField constraint to prevent duplicate votes
  • ForeignKey relationships for candidate integrity
  • Server-side validation enforcement
  • Authentication-based vote restrictions
  • CSRF protection implementation

Architecture Decisions

Django was chosen for its built-in authentication framework and robust ORM capabilities. Relational constraints were prioritised to ensure voting integrity at the database level, rather than relying solely on frontend restrictions.

A OneToOneField relationship was used to guarantee that each authenticated user could only submit one vote.

Security Considerations

  • Authenticated-only vote submission
  • Prevention of self-voting logic
  • Duplicate vote restriction
  • CSRF middleware protection
  • Server-side validation enforcement

Challenges & Solutions

Preventing both duplicate voting and candidate self-voting required layered validation. This was achieved through a combination of relational constraints and explicit backend logic checks before database commit.

Ensuring fairness while maintaining scalability required careful model structuring and separation of concerns.

Future Improvements

  • Migration to PostgreSQL for production scaling
  • Audit logging system
  • Role-based permission expansion
  • REST API integration
  • Rate limiting for submission protection
